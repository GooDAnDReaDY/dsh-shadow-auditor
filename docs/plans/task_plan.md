# Техническое задание и план реализации: dsh-shadow-auditor

## 1. Цели и назначение
Обеспечение безопасности и чистоты кодовой базы: фоновое выявление утечек секретов, хардкода персональных путей и блокировка деструктивных терминальных команд до их подтверждения.

## 2. Архитектура решения
- **Модуль `SecretScanner`**: правила регулярных выражений и энтропийный анализ для поиска API-ключей, токенов, приватных ключей и путей хоста (`/home/`, `/mnt/`, IP).
- **Модуль `CommandSafetyGuard`**: инспекция команд терминала перед запуском (проверка флагов `--force`, деструктивных манипуляций с ФС).
- **Интеграция с хуком `approval/asked`**: обогащение карточки подтверждения статусом безопасности (Green / Yellow / Red).

## 3. Декомпозиция задач (Work Breakdown Structure)
- [ ] **Этап 1: Анализаторы безопасности (Backend Guard Engine)**
  - [ ] 1.1 Реализация `SecretScanner` (база сигнатур токенов OpenAI, Anthropic, Gitea, GitHub, AWS, JWT, Private Keys).
  - [ ] 1.2 Реализация детектора инфраструктурных путей и IP-адресов.
  - [ ] 1.3 Модуль `CommandSafetyGuard` с набором запрещенных и опасных паттернов bash.
- [ ] **Этап 2: Инструменты агента (Agent Tools)**
  - [ ] 2.1 Тул `shadow_auditor_scan_diff` (проверка переданного diff на безопасность).
  - [ ] 2.2 Тул `shadow_auditor_check_command` (проверка команды перед исполнением).
  - [ ] 2.3 Тул `shadow_auditor_rules_list` (список активных правил безопасности).
- [ ] **Этап 3: Клиентский интерфейс (Frontend Web UI)**
  - [ ] 3.1 Бейдж безопасности (Security Shield Badge) в карточке подтверждения действия.
  - [ ] 3.2 Карточка настроек `settings.plugin.item` со списком правил и переключателями strict/warn.
  - [ ] 3.3 Модальное окно деталей аудита при обнаружении риска.
- [ ] **Этап 4: Тестирование и надежность**
  - [ ] 4.1 Тесты детекции различных типов секретов и приватных ключей.
  - [ ] 4.2 Тесты ложноположительных срабатываний на безопасных строках.
  - [ ] 4.3 Smoke-прогон `npm test` без внешних зависимостей.
